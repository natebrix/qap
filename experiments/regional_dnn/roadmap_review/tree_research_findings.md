# Search tree and adaptive computation: wil50/sko49

Research audit at ca50467, 2026-11-02 (America/Los_Angeles). No solver runs, repository mutations, remote writes, or new measured speedups. I inspected the current branch/bnb/DNN/estimate code, README and tuning histories, both roadmap memos, and sko49 feasibility notes; reanalysed the existing 1,410 wil50 child-bound records. Reproduction script: `tree_cache_analysis.py`. That analysis is cheap, deterministic, and uses existing measurements; its subtree costs remain model surrogates.

## Main conclusion

The most useful NEW implementation gate is **full conditional evaluation of a parent's certified dual**, before spending any child SDP iterations. It can screen children and price branching lines. It is materially different from the already-failed outer-LAP reduced-cost experiment. Combine it with tail-focused limited strong branching and parent cut inheritance; do not multiply those as independent gains.

The first operational prerequisite is to replace the gap-to-depth extrapolation with sampling of the actual solver policy. Existing estimates are dominated by one or two sampled nodes and the strongest full-subtree A/B starts at a different branching depth from the claimed global tree. Neither observation invalidates the 139,149 → 76,755 CPU-s A/B; both limit its extrapolation.

No tree-side experiment here demonstrates the remaining 3.83–12.18× needed to fit 574.56M reference-core-seconds (1,000 cores, one week, 95% useful utilization). A conditional portfolio can pursue that goal, but a promise based on multiplying guessed factors would be unsupported.

## 1. Three audit findings that change the experiment design

### 1.1 The measured subtree has a rebased branching schedule

`stronger_bounds/search/run_ab3.sh` passes `-F 39:27,30:48,25:49`, `PARAM/nug_deep.par`, and `-x 0:4:1:300:1`, with DNN extension20. `driver.C:451–477` fixes three assignments without increasing `node.depth`; the usage text explicitly says its depth is0. `pick_param` in `bnb.C:204–236` then forcibly chooses parameter block0 when `node.depth==0`. Thus that subtree root uses **rule4, up to30 candidate rows and30 columns**, while a global-depth3 node cannot use block0 because its maximum depth is2. Depending on relative gap, a global node selects block1 (rule7), block2 (rule6), or later. Descendant transitions are also shifted by three levels. The relative-gap baseline/root bound is rebased as well, so merely subtracting three from parameter depth limits is not a complete replay.

Consequences: the measured 1.81× cut benefit is valid for that exact local subtree policy. It is not a global wil50 cost estimate. It already has strong root lookahead, so adding the old eccentric→xbar estimated factor to this baseline is especially unjustified.

Correct test: create actual global frontier nodes by running the intended upper-tree policy, save/resume them with original depth, root bound, incoming QPB/DNN warm start, symmetry and cut state, then replay identical frontier states under A/B policies. For a small diagnostic, log `(nfix,depth,param block,rule,chosen line,root_bound)` at the existing -F root and compare an injected node with preserved global context. A synthetic depth fix alone can isolate one difference but is not the final benchmark.

### 1.2 The published line comparison is not actual rule4 lookahead

`lines.py:211–216` calls the largest **mean child QPB** among only2 U-ranked rows and2 U-ranked columns its “lookahead” pick. Actual `branch.C:2144–2334` uses `use_best` candidate lines and scores a child by `J3_child_dim*(bound+Uij)+best_u1_sum`; this includes grandchildren's U sums. It is not simply mean QPB. The cached ranking is still informative, but “rule4 is1.58× worse” is only a surrogate comparison.

Rule8 and rule9 already exist. Their implementation and nug28/nug30 A/Bs are old work, not new improvements to propose. In particular rule9 repairs much of rule8's nug28 regression; don't rediscover this as a new hybrid.

### 1.3 The whole-tree estimate is almost a one-node estimate

Replaying `sko49_feasibility/model.py` exactly at g=130:

| sample/model | share of model node total |
|---|---:|
| sko49, no extra bound, the337-short sample alone |82.96%|
| sko49, +130 cut gain, the337-short sample alone |80.37%|
| wil50, no extra bound,405- and329-short samples together |94.59%|
| wil50, +130, those two samples together |92.80%|

Removing the single hardest sko49 sample and renormalizing reduces its +130 estimate by4.67×. This is sensitivity, not a legitimate reason to delete the sample. It says spend the next measurement on that class: sko49 depth3 node5 `37:34,20:42,12:32`, converged336.9 short, not another easy node1 phase.

Also, depth3 sample generation fixes three random facilities and locations. Those nodes are not sampled from the distribution generated by adaptive rule4/7/8/9 with symmetry. Uniform random assignments, random-line depth4 children, cold fixed-iteration bounds, and solver-selected warm-started descendants answer different questions. Model `round(shortfall/g)` collapses their conditional distributions into one deterministic generation and can move an entire class by46× for a tiny gap change. The smooth47^(gain/130) formula is another surrogate, not a measured conversion from bound points to CPU.

## 2. New priority: full parent-dual conditional certificates

Current `child_lb` in `dnn.C:1067–1086,1543–1549` adds reduced costs of the *outer* GL assignment problem to the parent bound. The negative experiment (zero eliminations of2,209 assignments, largest increase2.8–6.5) rules out that cheap screen at those multipliers. It does NOT rule out recomputing every inner LAP after conditioning an assignment.

Let the parent certificate use scaled multiplier Zc, parent lifted objective L, spectral upper bound δ and parent trace τ=m_parent+1. Let M=L+scale*Zc, and let T embed child assignments with x_ij=1 into the parent. Then a valid child bound is

`parent_shift + GL_child(T' M T) − τ*scale*δ − rounding_margin`.

Reason: every feasible child lifts to a feasible parent, so the parent's spectral inequality still holds; GL_child minimizes the contracted polynomial over a relaxation containing all child-feasible points. T is the same affine-lift mapping already implemented in `dnn_warm_child`: child index0 represents parent0 plus parent assignment r=(ij); `M'00=M00+2M0r+Mrr` and `M'0a=M0pa+Mrpa`. All inner assignments now respect the fixing. A parent-certified spectral bound is reused, so no child eigensolve or ADMM iterations are required for this test.

Important implementation details:

* Snapshot the exact multiplier used by the selected certificate, its scale, spectral penalty and objective/cut constants. `DNNWarm::Z` is the iteration warm start; it is NOT automatically that certificate multiplier.
* Keep the **parent trace correction**, not `(m_child+1)δ`. Keep the parent shift and parent cut right-hand-side constants once; do not add a reduced-QAP shift again after contracting full L.
* Add conservative error allowances for contraction and all LAP operations to inherited certificate rounding allowances. Reject nonfinite values. Validate by tiny-instance enumeration and parent/child restriction identities.
* Use max(parent certified lb, conditional lb). A weak polyhedral evaluation can otherwise print a lower child bound without invalidating either certificate.
* Capture a cut-phase certificate too: uncut reduced-cost degeneracy may change after cuts. This targets the same dual-transfer mechanism as cut inheritance, so their factors overlap.

Gate: capture uncut and best cut certificates at wil50 parent10, parent1, sko49 node5, plus one nearly fathoming cut failure. Evaluate the two xbar candidate lines (≤94 distinct children); measure CPU, child-bound gain distribution, directly fathomed children, and ranking agreement with existing child DNN outcomes. No full all2,209 sweep initially. Kill as a pruning lever if it eliminates virtually none and median gains remain<10; it might still rank lines. Kill as a branching lever if rankings do not improve over existing QPB/xbar at materially smaller cost than short DNN probes. Do not assign an end-to-end factor before this measurement. The arithmetic is well founded; useful numerical strength is unmeasured.

## 3. Tail-focused adaptive strong branching: concrete evidence and limits

I reanalysed every stored child for the ten candidate lines at each of wil50 parents1,3,10. On each parent's best recorded line:

| parent | best cached line | children fathomed at300 iterations | maximum remaining gap | fraction of47^(gap/130) cost in five hardest children |
|---|---|---:|---:|---:|
|1,404.8 short |column45|0/47|347.6|76%|
|3,240.7 short |column45|31/47|269.9|92%|
|10,158.2 short |row49|33/47|189.0|87%|

These best lines remain best across gain-per-level100/130/160 and hypothetical uniform cut gains0/80/130. Thus the ranking signal isn't just one chosen exponential slope. But the magnitude of a gain remains model-dependent. This also shows why counting immediate fathoms is insufficient: parent3 column45 has31 cheap fathoms and a very expensive surviving tail.

New policy: shortlist xbar's row/column plus one genuinely different QPB candidate; screen all children with conditional certificates; allocate10–30 warm-started DNN iterations only to the5–8 predicted hardest/most uncertain children per candidate; continue probing only while plausible alternative lines differ by more than the probe's CPU cost. Keep the resulting child bounds/states when taking the selected line. Learn conditional cost by depth, parent gap, warm-start state, and cut status, not simply a universal g. Every predicted stop is a computation choice, never an uncertified prune.

Cheap offline evidence for a simpler scoring-only change is weak. Across all ten cached lines, **mean child QPB chooses the best line at all3 parents already**. Minimum child QPB chooses lines costing3.51×,1.22×,2.07× best; the bottom-five mean gives1.00×,1.22×,1.32×. An exponential QPB score with slope fit on the other two parents selects1.00×,1.00×,1.32×. Therefore “replace mean by worst child/tail exponential” is not a demonstrated gain. Actual DNN probes or better conditional certificates are needed; simple tail-score rhetoric is insufficient.

Gate the policy at the three original parents plus their hard surviving children and sko49 node5; compare actual chosen-line subtrees, preserve global depth, and charge all screening/probing time. A1.3–2× residual-tree reduction is a worthwhile experimental target, not an expectation established by the cache. Expensive all-lines/full-DNN strong branching is not justified.

## 4. New disjunction gate: group easy assignments by predicted difficulty

The previous region probe was negative on one nug30 node with fixed geometric2×3 blocks. That does not settle difficulty-based grouping on expensive wil50 children.

In the cached best line for parent3 and for parent10, the24 children with the highest child-QPB bounds **all24 fathom** at the300-iteration DNN budget. Group those assignments into one disjunct, represented by eliminating the other positions in that line. Certify that union once; keep the remaining23 children separate (or split the easy group if it does not fathom). This asks whether one restricted-parent solve replaces24 child solves. It is not a stronger mathematical lower bound than every singleton, and it cannot be assumed to match the weakest singleton bound.

Gate: try8-,16-,24-member high-QPB groups at parent3/column45 and parent10/row49, with current cuts and warm starts, using the existing dnntest elimination-mask support. Compare the entire group’s certification cost to the sum of measured singleton costs. Kill if the group remains below cutoff after a budget equal to~3 singleton costs; avoid geometric blocks and full binary-tree integration until the gate passes. If successful, add exact coverage/disjointness checks and persist masks. `bnb.C` does not currently wire general elimination masks into every DNN call, so this is an integration task, not an environment toggle.

Potential: large savings on a grouped easy class; whole-tree gains may be modest because hard children dominate descendants. It may become more valuable *after* inheritance/branching removes the expensive tail. No multiplicative gain assigned.

## 6. Allocation, symmetry, incumbent: avoid false multipliers

* **Continuation versus branching is an expected-CPU decision.** Spend Δt on another cut/quiet/probe step when its estimated probability of avoiding the residual subtree times that subtree’s expected CPU exceeds Δt, with conservative calibration. A false give-up can cost45 children, so thresholds fitted to four cold trajectories are not adequate. The existing gap-ratio failure on nug30 demonstrates this. Group actions by actual warm state and phase progress; log each phase's gap, primal estimate, active cuts, CPU and child outcome.
* **Inheritance** is already the leading untested roadmap proposal. It remains the first gate, but it is not new here and its monotone parent lower bound does not guarantee additive preservation of the child's uncut gain. Conditional certificate evaluation and tail probing are complementary ways to price it, not independent factors to multiply.
* **Symmetry is counted in the estimates, not universally implemented in these runs.** There is no `latest/SYM/wil50.sym`; run_ab3 explicitly says no symmetry. That is harmless for a generic fixed-depth3 subtree, where stabilizers are normally trivial, but a real global run must implement the assumed factor4. sko49's generated symmetry file applies to the transposed instance, side1 cuts; generic root runs on the original orientation do not automatically get8×. Verify exact orbit coverage/stabilizers. Do not multiply either factor into a model already divided by4/8. Flipping instance orientation also exchanges row/column branching interpretations.
* **Incumbent heuristics** are not a planned source of the required gain when all studies use the best-known upper bounds48816/23386. A rare better feasible assignment could help enormously, but assuming it exists is not a proof-budget plan. Run a modest existing SA/local-search verification budget if useful; stop rather than consume the hard-node research budget indefinitely.
* **No remaining cheap outer reduced-cost fix:** QPB and DNN outer-LAP screens were measured negative. **No new global symmetry factor:** the grid groups have already been priced. **No repeating rule8/9 as new work.**

## Recommended decision sequence

1. Correct replay/global-frontier sampling and phase logging, preserving the measured A/B as a local control.
2. Test inherited cut certificates/pools AND full conditional-dual certificates on the named hard classes.
3. Only if useful, test tail-limited strong branching with charged overhead and retained child states.
4. Run the two easy-group disjunction probes as a low-budget optional gate.
5. Recompute a directly sampled CPU estimate; claim a one-week route only if its conservative range fits the target after measured per-node speed improvements. A phase-only optimization cannot provide the whole required factor: phases46% of node10 cut-arm CPU means infinite phase acceleration is bounded by1.85× there.
